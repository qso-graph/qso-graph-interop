# C ABI

`qso-graph-interop-ffi` lets C and C++ applications, and language runtimes with a C
FFI, use the public protocol codecs without a Rust runtime or Rust toolchain at
application runtime. It provides shared and static libraries. Callers own I/O,
destinations, request execution, clocks, and control policy.

Include `crates/qso-graph-interop-ffi/include/qso_graph_interop.h`. The checked-in
header is generated by cbindgen 0.29.4. Maintainers regenerate it with
`cargo xtask ffi-header --write`; `cargo xtask ffi-header`, full verification,
and CI compare fresh generation with that file. Consumer applications do not run
cbindgen. The header supports C11 and C++11, with C linkage in C++.

## Version check

Before using handles or buffer layouts, require
`qgi_abi_version() == QGI_ABI_VERSION` (currently 1). Zero means the version query
failed. Reject a different ABI before any other operation. `qgi_version` returns
the package version as UTF-8 in an owned buffer; it is independent of the ABI.
An incompatible change to signatures, layout, status meanings, or ownership
increments the ABI number. Compatible additive functions can retain the ABI;
callers must still check that their required symbols are available.

## Functions

All status-returning functions return `int32_t`. Handles are opaque `uint64_t`
tokens, not addresses. Every input and output pointer is checked for its applicable
null, alignment, byte-size, and address-overflow conditions before access.

| Function | Input and result |
| --- | --- |
| `qgi_abi_version` | ABI number; does not change last-error text. |
| `qgi_version` | Required output buffer; package version text. |
| `qgi_last_error` | Borrowed error view for the current thread; does not change it. |
| `qgi_codec_new` | Explicit-length UTF-8 family name and required handle output. Families: `wsjtx`, `n1mm`, `fldigi`, `qgi` (TCP), `qgi-udp`. |
| `qgi_codec_free` | Release the handle. Zero, invented, and stale tokens return `QGI_BAD_HANDLE`. |
| `qgi_decode` | Native bytes and decode-options JSON; required owned JSON outcome output. |
| `qgi_encode_command` | Event JSON, family encoding-options JSON, request index, required request-count and native-buffer outputs. |
| `qgi_encode_event` | Event JSON and re-encoding-shaped options; required QGI carriage-buffer output. |
| `qgi_reencode` | Observed event JSON and re-encoding options; required native-buffer output. |
| `qgi_reset` | Handle and optional raw session bytes. NULL/0 resets all sessions; a non-NULL pointer with zero length selects an empty session. |
| `qgi_decode_stream` | Caller buffer, EOF flag, decode options, required consumed-byte and outcome-buffer outputs. |
| `qgi_buffer_free` | Release one complete buffer descriptor returned by this library. |

## Bytes, JSON, and ownership

Lengths are byte counts of type `size_t`, never character counts. Names, JSON,
version text, and error text are UTF-8 without terminating NUL bytes. Native input
and output are raw bytes and can contain NUL or invalid UTF-8. JSON uses the
specification's representations for raw text and native evidence. Missing keys,
JSON `null`, empty strings, invalid UTF-8 byte arrays, invalid UTF-16 unit arrays,
all family fields, and trailing extensions retain their distinct meanings.

Inputs are borrowed only during a call and must remain readable and unchanged
until it returns. NULL with length zero represents empty input. An empty options
input uses defaults. An empty native message is passed to the codec, which may
return `QGI_TRUNCATED` or a family validation error. Empty family names and empty
event JSON are invalid. NULL with nonzero length is rejected. Each input is
bounded by `QGI_MAX_BUFFER` (1,048,578 bytes), with tighter limits of 32 bytes for
family names and 1,048,576 for JSON. Family parsers apply their own native limits;
context objects are limited to 4,096 compact JSON bytes.

Required outputs must point to aligned writable storage for exactly their declared
type. Input allocations and output slots must be disjoint; output slots must also
be disjoint from each other. The caller must supply live, correctly sized
allocations: numeric checks cannot detect dangling or unmapped foreign memory.
Violations of this allocation contract, including foreign data races, are outside
the ABI's recoverable error contract.

After all required output pointers pass validation, ordinary failures clear the
outputs. A stream framing error can additionally report consumed bytes. When an
output pointer itself is invalid, other output slots need not be changed. Release
any previous owned result before reusing its output slot.

A `QgiBuffer` contains an immutable data pointer, byte length, and ownership token.
It remains valid until its matching `qgi_buffer_free`, independently of codec
reset or destruction. Release it exactly once through the same loaded library
instance. Never use `free`, `delete`, a language runtime allocator, or a different
library version. Copying the descriptor does not duplicate ownership. A stale or
modified descriptor returns `QGI_BAD_BUFFER`; the allocation is not released on a
mismatch. A zero descriptor `{NULL, 0, 0}` can be released. Finish all buffer reads
before freeing it, including reads from other threads. Unloading the library
requires releasing all its handles and buffers first.

The process can hold at most 4,096 handles and 4,096 owned buffers simultaneously.
Tokens are never reused within a library instance. Resource or token exhaustion
returns `QGI_BUFFER_TOO_LARGE`. There is no implicit eviction.

## Decode and command representations

`qgi_decode` returns one compact JSON object:

```json
{"events":[],"skips":[]}
```

Events are specification event objects. Skips include `reason`, `native_version`,
`native_type`, `native_name`, `set_index`, and `record_index`, with unavailable
metadata set to null. A skip is a successful outcome, not a status failure. To
write specification NDJSON, serialize each member of `events` on its own line;
the outcome wrapper and skip metadata are ABI data, not specification records.

Decode options wrap the caller's context and family metadata:

```json
{
  "context": {"direction":"from_application","exchange":"response"},
  "native": {"request":{"method":"rig.get_frequency"}},
  "structured": true,
  "expiry": 1
}
```

All keys are optional. Default context has unknown direction and exchange.
`native.request` associates fldigi responses with the caller's original request;
its contents follow the public fldigi API and Annex E. Unknown decode-option keys
are errors. The `session` key is reserved and rejected; current family codecs do
not require session metadata. Handles retain codec state across calls and reset
clears it through the public codec interface.

Commands are specification event objects, without observed `native` evidence.
Encoding options are the family-native object, such as `{"schema":3}` for WSJT-X.
Empty options use family defaults. Pass request index zero to get the first native
buffer and total request count. For fldigi, request subsequent indexes in order;
execute and correlate each independent XML-RPC body yourself. Each successful
call creates a separately owned buffer. An index outside the count returns
`QGI_INVALID_VALUE`. Encoding calls do not execute commands or mutate codec state.

Re-encoding options have optional `encode` and `decode` objects. `encode` contains
family encoding options; `decode` uses the decode-options shape above. This allows
fldigi response re-encoding with the same explicit request association. Re-encoding
uses the public family verification and native-evidence preservation paths. The existing QGI
encoding entry points retain their forwarding behavior. New callers can select carriage explicitly
with `qgi_encode_event`, which requires a QGI handle. It uses the original family's profile and the
per-call association in `decode` for authored evidence checks. Its event JSON and framing bytes
match the Rust carriage API. Native command encoding and evidence re-encoding remain distinct
operations in the Rust interface.

For `qgi_decode_stream`, retain your own receive buffer. Pass its current contents
and EOF as 0 or 1. Remove exactly `consumed` bytes after each call, including a
framing failure. The call consumes at most one complete frame; call again on any
remaining bytes. Success with an empty output means no event was produced. Zero
consumption means retain the bytes and append more data; it is not EOF. A partial
frame at EOF returns `QGI_TRUNCATED` and consumes that partial frame. An oversized
unterminated frame is consumed and the codec discards through the next newline;
`qgi_reset` clears that recovery state. Supply large streams in chunks no larger
than `QGI_MAX_BUFFER`. The library does not retain the caller buffer.

## Status codes and panic behavior

These numbers and meanings are stable within ABI 1. Codes 1–5 match the core error
categories. The header defines every constant.

| Code | Name | Meaning |
| ---: | --- | --- |
| 0 | `QGI_OK` | Success, including skipped messages or incomplete stream input. |
| 1 | `QGI_TRUNCATED` | Incomplete native input or unfinished frame at EOF. |
| 2 | `QGI_OVERSIZED` | Core message, field, parser, or context resource limit. |
| 3 | `QGI_MALFORMED` | Malformed native or event/options JSON syntax. |
| 4 | `QGI_UNSUPPORTED_VERSION` | Unsupported command or family version. |
| 5 | `QGI_INVALID_VALUE` | Invalid event, option, UTF-8 text, family, or request index. |
| 100 | `QGI_NULL_POINTER` | Required pointer is NULL. |
| 101 | `QGI_BAD_HANDLE` | Handle is zero, invented, freed, or invalidated by panic. |
| 102 | `QGI_BUFFER_TOO_LARGE` | ABI input length or outstanding-resource limit. |
| 103 | `QGI_BAD_BUFFER` | Unknown, stale, or altered owned-buffer descriptor. |
| 104 | `QGI_PANIC` | Contained Rust unwind; the affected codec is invalidated. |
| 105 | `QGI_INVALID_POINTER` | Misaligned output or overflowing input/output address range. |

`qgi_last_error` returns a borrowed `QgiError` with an explicit length and no NUL.
Copy it before the next call on the same thread, except `qgi_last_error` and
`qgi_abi_version`, which preserve it. It also expires at thread exit. Never free
this view or pass it to `qgi_buffer_free`. Success clears the calling thread's
last error; a failure replaces it. Errors on other threads do not affect it.
Messages are diagnostic text, not stable machine-readable error identifiers.

Every export contains unwinding Rust panics with `catch_unwind`. Status operations
return `QGI_PANIC`; an affected codec handle becomes invalid and must be replaced.
Other handles and owned buffers remain valid. ABI-version and last-error queries
return zero/empty fallback values on panic. Process abort, allocator abort/OOM,
and caller allocation-contract violations cannot be converted to status codes.

## Threads and reentrancy

Handles can be created, used, reset, and released on different threads without
external locking. An internal registry mutex serializes all codec operations,
including operations on different handles. Concurrent free is safe but can make a
competing operation return `QGI_BAD_HANDLE`. Callers that need an application-level
order must impose that order themselves. Immutable returned buffers can be read
concurrently; coordinate their final release with all readers. There are no
callbacks or callback lifetimes. Calls do not invoke foreign code; reentry into a
running call, for example from a signal handler or panic hook, is unsupported.

## C example

This program creates a codec, decodes a schema-3 WSJT-X HaltTx datagram with an
empty wire ID, writes the JSON outcome, and releases both resources.

```c
#include "qso_graph_interop.h"
#include <stdio.h>

int main(void) {
    if (qgi_abi_version() != QGI_ABI_VERSION) return 1;
    QgiCodec codec = 0;
    QgiBuffer out = {0};
    const uint8_t name[] = "wsjtx";
    const uint8_t packet[] = {
        0xad,0xbc,0xcb,0xda, 0,0,0,3, 0,0,0,8, 0,0,0,0, 1
    };
    int32_t status = qgi_codec_new(name, sizeof name - 1, &codec);
    if (status != QGI_OK) return 1;
    status = qgi_decode(codec, packet, sizeof packet, NULL, 0, &out);
    if (status == QGI_OK) {
        fwrite(out.data, 1, out.len, stdout);
        putchar('\n');
    } else {
        QgiError error = qgi_last_error();
        fwrite(error.data, 1, error.len, stderr);
    }
    qgi_buffer_free(out);
    qgi_codec_free(codec);
    return status == QGI_OK ? 0 : 1;
}
```

## Build and link

Maintainers build matching artifacts with
`cargo build -p qso-graph-interop-ffi --release --locked`. Distribute the header and
the library for the consumer's target architecture and operating system. Users of
those artifacts need only their platform C/C++ compiler or language FFI loader.
No Rust installation is needed to load the shared library or link the static one.
Use the platform C calling convention; map `size_t` to the target pointer width
and `QgiCodec`/buffer tokens to unsigned 64-bit values.

On Linux, the shared library is `libqso_graph_interop_ffi.so` and the static library
is `libqso_graph_interop_ffi.a`. For the example saved as `example.c`:

```sh
cc -std=c11 -Icrates/qso-graph-interop-ffi/include example.c \
  -Ltarget/release -lqso_graph_interop_ffi \
  -Wl,-rpath,'$ORIGIN' -o example
```

Place the `.so` beside the executable for that runtime search path. For static
linking, replace `-L... -l...` and the runtime search option with the explicit
archive path, followed by `-ldl -lpthread -lm`.

On macOS, use `libqso_graph_interop_ffi.dylib` or the `.a` archive:

```sh
cc -std=c11 -Icrates/qso-graph-interop-ffi/include example.c \
  -Ltarget/release -lqso_graph_interop_ffi -o example
```

Set the dylib install name and application runtime search paths for your packaging
layout (typically `@rpath` or `@loader_path`); sign the packaged artifacts as your
application requires. Static links use the explicit archive and the platform
system libraries, including `-lSystem -liconv`.

On Windows MSVC, distribute `qso_graph_interop_ffi.dll` and its import library
`qso_graph_interop_ffi.dll.lib`. In a Visual Studio developer command prompt:

```bat
cl /I crates\qso-graph-interop-ffi\include example.c /link /LIBPATH:target\release qso_graph_interop_ffi.dll.lib
```

Place the DLL beside the executable. The static alternative is
`qso_graph_interop_ffi.lib`; link the target's Rust standard-library system imports
as well (including `advapi32`, `bcrypt`, `kernel32`, `ntdll`, `userenv`, and
`ws2_32`). Static-library producers should record the full target-specific list
from `cargo rustc -p qso-graph-interop-ffi --release -- --print native-static-libs`
with their artifacts. Match the consumer's architecture and C runtime toolchain.
The DLL and import-library approach avoids maintaining that static import list.

## Verification

`cargo xtask verify` builds the FFI crate, checks header regeneration, compiles and
runs the C consumer against the static archive, and compiles the header as C++
with `c++ -fsyntax-only`. Missing `cc` or `c++` fails with an installation hint.
Rust tests exercise the ABI's invalid pointers, lengths and tokens, thread-local
errors, cross-thread use and frees, panic containment, stream recovery, and
independent decode/command vectors for each required family. Policy and header
checks include planted failures. CI runs the same steps; native consumer steps
run on Linux, and Rust ABI tests run on Linux, macOS, and Windows.

The full verifier retains the existing 60-second fuzz smoke for each native
family. Miri checks every C entry point using minimal family inputs, invalid
arguments, ownership and panic cases, stream decoding, and multiple fldigi
requests. Vector sweeps and large stream frames run in the ordinary test suite.
The linked C consumer also runs under Rust AddressSanitizer and C ASan/UBSan
on Linux x86_64 GNU. Both memory tools must diagnose a planted heap overread.
Install the system sanitizer runtimes (`libasan` and `libubsan` on Fedora/RHEL,
or your distribution's equivalents) alongside a sanitizer-capable C compiler.
The shipped compiler remains Rust 1.99.1; Miri, sanitizers, and isolated fuzzing
use the pinned nightly-2026-10-30 toolchain.
